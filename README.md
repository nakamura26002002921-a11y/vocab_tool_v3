# vocab_tool_v3

Web検索結果とGroq(LLM)を使って、単語帳データ(CSV)を自動生成するツール群です。

- `run_ru2ja.py` : ロシア語単語 → 日本語向け解説(ロシア語学習者向け)
- `run_ja2ru.py` : 日本語単語 → ロシア語向け解説(日本語学習者向け)
- `search.py` : DuckDuckGoでWeb検索し、上位ページの本文をスクレイピングするコマンドラインツール(上記2つから呼び出される)
- `vocab.py` : Groqに単発でプロンプトを投げるだけの簡易スクリプト

## できること

単語リスト(`words.txt`)を読み込み、各単語について

1. `search.py`でWeb検索し、意味・語源・コロケーションに関するページ本文を集める
2. 集めた情報をGroq(`openai/gpt-oss-120b`)に渡し、以下の項目をJSON形式で生成させる
   - 単語 / 読み方(日→露のみ) / 意味 / 品詞 / 語源 / コロケーション3つ / 例文2つ(訳付き)
3. 結果をCSVに1行ずつ追記する

途中で検索やAPI呼び出しが失敗しても、該当の単語だけスキップして処理を続行します(詳細は[エラー処理について](#エラー処理について)を参照)。

## セットアップ

### 必要なパッケージ

```bash
pip install groq requests beautifulsoup4 ddgs
```

### Groq APIキー

`run_ru2ja.py` と `run_ja2ru.py` の先頭にある `API_KEYS` にAPIキーを設定してください。

```python
API_KEYS = [
    "gsk_xxx",
    "gsk_yyy",
    "gsk_zzz",
]
```

複数キーを設定すると、単語ごとに順番に使い回してレートリミットを緩和します(1つでも動作します)。

> **注意**: APIキーをGitにコミットしないでください。公開リポジトリで使う場合は環境変数から読み込む形に変更することを推奨します。

## 使い方

### 1. 単語リストを用意する

`words.txt`(1行1単語)を作成します。

```text
привет
спасибо
дом
```

`--words`オプションで別のファイル名を指定することもできます。

### 2. バッチ処理を実行する

**ロシア語 → 日本語向け解説**

```bash
python3 run_ru2ja.py --output result.csv --words words.txt --startidx 1 --endidx 10
```

**日本語 → ロシア語向け解説**

```bash
python3 run_ja2ru.py --output result.csv --words words.txt --startidx 1 --endidx 10
```

#### 主なオプション

| オプション | 必須 | 説明 |
| --- | --- | --- |
| `-o`, `--output` | ✓ | 出力CSVファイルのパス(追記モード) |
| `--words` | | 単語リストファイル(デフォルト: `words.txt`) |
| `--startidx` | ✓ | 処理開始する単語の行番号(1始まり) |
| `--endidx` | ✓ | 処理終了する単語の行番号(この行を含む) |
| `--interval` | | 単語ごとの待機秒数(デフォルト: 30秒。レートリミット対策) |
| `--fail-log` | | 失敗した単語を記録するログファイル(デフォルト: `failed_words.tsv`) |

大量の単語を一度に処理する場合、`--startidx`/`--endidx`で範囲を区切って何回かに分けて実行するのがおすすめです(処理途中で落ちても被害を最小限にできます)。

### 3. 出力されるCSVの列

**`run_ru2ja.py`**

| 列 | 内容 |
| --- | --- |
| 1 | ロシア語の単語 |
| 2 | 日本語訳 |
| 3 | 品詞 |
| 4 | 語源 |
| 5 | コロケーション(`; `区切り、3つ) |
| 6 | 例文1(ロシア語) |
| 7 | 例文1の日本語訳 |
| 8 | 例文2(ロシア語) |
| 9 | 例文2の日本語訳 |

**`run_ja2ru.py`**

| 列 | 内容 |
| --- | --- |
| 1 | 日本語の単語 |
| 2 | 読み方(ひらがな) |
| 3 | ロシア語での意味 |
| 4 | 品詞 |
| 5 | 語源 |
| 6 | コロケーション(`; `区切り、3つ) |
| 7 | 例文1(日本語) |
| 8 | 例文1のロシア語訳 |
| 9 | 例文2(日本語) |
| 10 | 例文2のロシア語訳 |

`run_ja2ru.py`はLLMへのプロンプトをロシア語で記述しています(日本語学習中のロシア語話者向け解説を想定しているため)。一方でWeb検索クエリは日本語キーワード(`意味`・`語源`・`使い方 コロケーション`・`例文`)を使用しています。ロシア語キーワードで検索すると翻訳サイトなどで無関係な訳語がヒットしやすく、LLMが対象単語を別の単語と混同する(ハルシネーション)原因になりやすいためです。

### 4. `search.py`単体での利用

デバッグ等でWeb検索結果だけ見たい場合は単体でも実行できます。

```bash
python3 search.py --word "спасибо значение" --max-results 5 --max-words 200
```

## エラー処理について

`search.py`・`run_ru2ja.py`・`run_ja2ru.py`はいずれも以下の方針でエラーを扱います。

- **Web検索(DuckDuckGo)の失敗**: 最大2回リトライ。失敗し続けた場合はその検索クエリの結果を空として扱う
- **ページ本文のスクレイピング失敗**: 最大2回リトライ。失敗し続けた場合はそのページの本文を空文字として扱う(検索結果自体は残る)
- **Groq API呼び出しの失敗**(レートリミット・接続エラー・タイムアウト等): 最大3回リトライ(レートリミット時はより長く待機)
- **Groq応答のJSON解析失敗・必須項目の欠落**: リトライせず、その単語はスキップ
- **単語の混同(ハルシネーション)検出**(`run_ja2ru.py`のみ): LLMが応答した`word`が入力した単語と一致するか、例文中に対象単語が実際に含まれているかを機械的にチェックする。不一致の場合はハルシネーションの疑いとしてリトライせずスキップする
- **上記いずれかで最終的に失敗した単語**: 処理を止めずにスキップし、`--fail-log`で指定したファイル(デフォルト`failed_words.tsv`)に日時・行番号・単語・エラー内容をタブ区切りで記録して次の単語に進む
- 処理完了時に成功/失敗件数のサマリーをログ出力する

失敗した単語だけ再処理したい場合は、`failed_words.tsv`を見て該当単語を`words.txt`から抜き出し、別途`--startidx`/`--endidx`を指定して再実行してください。

## ファイル構成

```
.
├── README.md
├── search.py        # Web検索・スクレイピング
├── run_ru2ja.py      # ロシア語→日本語向け 単語帳生成バッチ
├── run_ja2ru.py      # 日本語→ロシア語向け 単語帳生成バッチ
├── vocab.py          # Groqへの単発プロンプト実行スクリプト
└── words.txt          # 単語リスト(各自用意)
```
